# Release notes — Phase 3: Sequential Recommendation and SASRec Ablation

> Synthetic-data research prototype for a fictional Indonesian commercial bank's mobile
> banking application. Nothing in this release is evidence about real customers or real
> banking systems, and nothing here is a production recommendation service.

## What is included

- **Sequential pipeline** (`bri.seq`): next-event sequence cases shared with the
  evaluator (strict history, unordered timestamp ties, history-only session
  boundaries), and a deterministic CPU/CUDA runtime with a runtime fingerprint.
- **Models**: SASRec Full plus four controlled ablations (NoPosition, Shuffled,
  MeanPool, SessionBoundary) with shared initialization and a multi-positive
  full-softmax loss.
- **Experiment discipline**:
  - seed namespaces reserved before any data existed;
  - Optuna TPE search on tuning validation splits only;
  - configuration frozen in a pinned manifest before final data;
  - gated final run (tests, CUDA tests, manifests, device, versions, runtime);
  - final test splits used once and locked.
- **Results**: 30 final datasets (3 behavior profiles × 10 seeds). Classical baselines
  and five SASRec variants, next-event (primary) and 7-day window (secondary)
  protocols, within-seed paired bootstrap and across-seed Student-t intervals, and
  within/cross-session strata.

## Headline result (synthetic)

SASRec beats Personal Frequency clearly only on `transition_dominant` / NBS: next-event
NDCG@1 0.400 vs 0.235, +0.164 [+0.152, +0.176] across seeds, 10/10 seeds. The gain
comes from within-session transitions. In the habit and balanced regimes, on
cross-session targets, and in the window protocol, Personal Frequency is as good or
better. Order and attention matter (Full > Shuffled, MeanPool); explicit positional and
session-boundary embeddings add nothing measurable in this setup.

## Known limitations

1. Synthetic data only.
2. One SASRec training seed: initialization variation is not measured.
3. Small NBP training sets and few within-session NBP cases.
4. Temporal history-length shift between training and evaluation.
5. Bit-identical reproduction is shown only on the same runtime. Other GPUs or
   CPU-vs-GPU runs produce different weights, and this is documented, not a bug.
6. Classical-model training cost was not instrumented, so the cost comparison is
   qualitative on the classical side.

## Reproduce

See `docs/12_PHASE_3_SEQUENTIAL_REPORT.md` §10. In short: install the `seq` extra, run
`python -m bri.experiments.integrity`, `pytest -q` and `pytest -q -m cuda`, then
`python -m bri.experiments.phase3 run --output-dir <new dir> --profiles <p> --seeds <s>`.

## Not in this release

Phase 3.1 (hybrid Personal Frequency + SASRec) is future work. Its gate may only use
pre-recommendation features, never the evaluator's within/cross-session label, and it
needs fresh seeds. Policy engine, explanation layer, API and dashboard are later phases.
